предметная область подключается словарями параметров и промпт-шаблонами.

## Быстрый старт

```bash
cargo test --workspace          # 153 теста, ничего внешнего не требуют

# посмотреть, что порождает невидимый слой
cargo run -p synthforge-params --example preview -- role-doctor 3
cargo run -p synthforge-params --example preview -- role-doctor 500 --stats

# проверить связь с провайдерами
$env:XAI_API_KEY='xai-...'
cargo run -p synthforge-llm --example smoke
```

Требуется Rust 1.85+. Внешних сервисов для сборки и тестов не нужно.

## Цикл «посмотрел → доработал» уже работает

Живые прогоны вскрыли девять дыр. Каждая закрыта словарём или проверкой, а не
подкруткой промпта — то есть закрыта навсегда, а не на один раз.

| Что увидели в выдаче | Чем закрыто |
|---|---|
| «психиатр» при «опыт в психиатрии: нет» | жёсткое правило связности |
| стаж 9 лет при 6 местах работы | правило соразмерности, а не просто «меньше стажа» |
| 40% популяции многодетные | веса по значениям вместо равномерного распределения |
| текст пересказывает список параметров | `mention: background`, подача директивами |
| «специалист украинского происхождения» | то же: происхождение стало фоном |
| «более двадцати лет» при стаже 18 | проверка числовых утверждений, в том числе словесных |
| ложная отбраковка «в 48 лет пришёл» | правило учло возраст в момент события |
| 57 лет при стаже 2 года | корреляции стажа с возрастом |
| модель выдумала имя | справочник имён по поколениям |

Последнее — характерный пример. Попросить модель придумать 10 000 имён значит
получить полторы сотни разных, все из числа самых частотных и без связи с годом
рождения. Справочник даёт 85 тысяч сочетаний и сдвигает моду: у рождённых в
1955 это Владимир и Юрий, у рождённых в 1995 — Артём и Никита. Отчество берётся
от имени отца, сэмплированного на поколение раньше.

## Nexorium

Основное хранилище — своё пространство в Nexorium. Доступ (`NEXORIUM_SPACE`,
`NEXORIUM_KEY`) — только в `.env`; `forge` читает его сам.

```
cargo run -p synthforge-nexorium --example provision -- create   коллекции всех видов
cargo run -p synthforge-nexorium --example provision -- smoke    проверка записи на временной коллекции
forge upload [коллекция…]                                       залить out/*.jsonl (повтор безопасен)
```

Когда доступ есть, `forge run` пишет в Nexorium и держит копию в `out/` для
сборки центров, страниц и съёмки; в копию попадает только то, что легло в базу.
Ключ сущности (`natural_key`) в Nexorium уникален: повтор пачки после обрыва не
создаёт дублей, а те, кто уже в базе, засчитываются как записанные.

## Агент по протоколу

`forge mcp` — MCP-сервер поверх stdio. Агент получает те же рычаги, что человек
в консоли: план, запуск, ход прогона, пауза, готовые записи, пометки приёмки.

| Инструмент | Что делает | Деньги |
|---|---|---|
| `kinds`, `plan` | виды сущностей; параметры будущих сущностей без вызова модели | нет |
| `run` | прогон в фоне, сразу возвращает сессию | **да, `budget_usd` обязателен** |
| `sessions`, `progress` | список прогонов, ход прогона и расход | нет |
| `pause`, `resume` | пауза встаёт после текущей пачки; снятие доделывает остаток | `resume` — да |
| `show` | готовые записи сессии | нет |
| `mark`, `feedback` | пометка приёмки (брак — только с метками), сводка | нет |

Ограничения против ошибок агента: не больше 50 сущностей за вызов (массовые
прогоны запускает оператор), без бюджета прогон не стартует, брак без меток не
принимается. Пометки агента ложатся в ту же базу, что и пометки людей.

Подключение в клиенте MCP (запуск из корня проекта, ключи — из окружения):

```json
{
  "mcpServers": {
    "synthforge": { "command": "target/release/forge", "args": ["mcp"] }
  }
}
```

## Невидимый слой

Уникальность берётся из **комбинаторики параметров**, а не из набора заготовок.
Рабочий словарь врача — 42 параметра, 38 из них задаёт код, 4 пишет модель.
Расширенная версия на согласовании — 81 параметр, см.
[ПАРАМЕТРЫ_ВРАЧА.md](ПАРАМЕТРЫ_ВРАЧА.md). Такие же черновики v2 есть для
консультанта, психолога, руководителя, здания и программы —
[ПАРАМЕТРЫ_V2.md](ПАРАМЕТРЫ_V2.md); включаются видом с суффиксом
(`forge run director-v2 5`).

Три части, и третья не менее важна первых двух:

1. **параметры** — чем описывается сущность;
2. **диапазоны** — какие значения допустимы;
3. **правила связности** — у врача 12 жёстких правил и 25 корреляций.

Без третьей части двести независимых параметров дадут врача 25 лет с
30-летним стажем. Жёсткие правила запрещают невозможное («психиатр без
психиатрического опыта»), мягкие делают правдоподобное более вероятным
(«многодетность повышает шанс подростковой практики»).

Словари лежат в [`dictionaries/`](dictionaries/) как JSON и правятся руками без
пересборки. Выражения пишутся текстом:

```json
{
  "name": "стаж_не_больше_возможного",
  "expr": "experience_years <= age - 24",
  "message": "медицинское образование занимает не меньше шести лет"
}
```

Общие части вынесены и переиспользуются: `human-core` и `human-visual` одни на
все роли, роль подмешивает их через `extends` и добавляет своё.

### Что делает код, а что модель

Весь слой работает **до** первого обращения к модели. К моменту, когда строка
готова, уже решено, каким будет человек. Модель не выбирает факты — она их
излагает.

| Задача | Кто | Почему |
|---|---|---|
| разложить «20% с опытом от 7 лет» по 300 строкам | **код** | модель не удерживает пропорции |
| выбрать возраст, образование, стаж | **код** | нужна согласованность полей между собой |
| проверить инварианты | **код** | модель не видит собственных расхождений |
| написать биографию | модель | это и есть её работа |

### Проверка словаря при загрузке

Ошибка в словаре размножится на всю популяцию, поэтому ловится при загрузке:
дубликаты ключей, ссылки на несуществующие параметры, опечатки в названиях
вариантов, несовместимые сдвиги, пустые диапазоны.

Отдельно — **порядок объявления**: если условие корреляции опирается на
параметр, объявленный позже цели, правило молча не сработает. Это худший вид
поломки: контент тихо становится хуже, и заметить нечем. Загрузка падает.

## Внешность отдельным словарём

Половина параметров `human-visual` существует ради одной задачи: не дать модели
выдать вылизанный стоковый портрет. В списках намеренно **нет** вариантов
«идеально симметричное лицо», «идеальная укладка» и широкой дежурной улыбки —
именно они выдают генерацию.

Вместо этого: асимметрия, состояние волос, мешки под глазами, цвет лица, особые
приметы, обстановка снимка и характер съёмки (студийная — редкая).

При генерации портрета модель получает **два вектора**: кто это по жизни и как
он выглядит. Параметры биографии в промпт портрета не уходят, и наоборот.

## Возобновляемость

Единица работы — строка в `jobs`. Воркер захватывает задания атомарным
`UPDATE … RETURNING`, при падении процесса они остаются в `running`, и
`Store::reap` возвращает их в очередь. Отдельного механизма чекпоинтов нет.

Проверено тестами `concurrent_claims_never_overlap` и
`reaper_returns_jobs_abandoned_by_dead_worker`.

## Деньги

Цены живут в [`config/model-catalog.json`](config/model-catalog.json), не в коде.
Модель, которой нет в каталоге, использовать нельзя — клиент к ней не создастся.
Иначе расход посчитался бы нулём и бюджетный потолок не сработал бы.

**Цены в каталоге не сверены.** Приложение сообщает об этом при старте. Перед
первым массовым прогоном их нужно проверить в консоли провайдера и проставить
дату в поле `verified`.

Маршрутизация — [`config/routing.json`](config/routing.json): тексты на Grok
(объём огромен, важна цена токена), изображения на OpenAI.

## Исходящий доступ — открытый вопрос

С сервера провайдеры недоступны:

| Эндпоинт | Ответ |
|---|---|
| `api.openai.com` | 403 `unsupported_country_region_territory` |
| `api.x.ai` | таймаут, соединения нет |
| `api.anthropic.com` | 403 `Request not allowed` |
| Gemini | 403 «нужен ключ» — то есть **доступен** |

На сервере это не решено никак: WireGuard не настроен, прокси в конфигах нет.
Четыре сервиса выключены именно поэтому.

С машины разработчика оба провайдера доступны, поэтому разработка не заблокирована.
Адрес прокси задаётся переменной `OUTBOUND_PROXY` и в код не зашит.

## Развёртывание

Сервер, доступ и особенности канала — в инструкции по серверу. Существенное:

- контейнер публикуется через общий `caddy-gateway`, порт наружу не пробрасывается;
- в `Caddyfile` нужны увеличенные таймауты — прогоны длинные;
- **бэкап `Caddyfile` до правки** и `caddy validate` до `caddy reload`;
- канал рвётся регулярно: сборку запускать отсоединённо, заливку с повторами.

Последнее — причина, по которой в клиенте Nexorium есть `verify_batch`.
