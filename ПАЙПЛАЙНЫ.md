# Пайплайны генерации и фундаментальный слой

Первая версия. Разбор на живом примере — генерация персонала.

---

# Часть 1. Фундаментальный слой

Это то, что **никогда не публикуется**, но из чего порождается всё остальное.
Ни один элемент этого слоя не попадёт ни на одну страницу. При этом каждая
сгенерированная сущность — его экземпляр.

Без него генерация — это независимые броски кубика: десять тысяч сущностей без
внутренней логики, где центр для престарелых укомплектован людьми, у которых в
биографии написано «работаю с подростками». С ним — популяция, у которой есть
устройство.

Слой состоит из пяти частей.

## 1.1. Справочники реального мира

Не выдумываются. Импортируются один раз и живут как данные.

- регионы, города, население, тип местности, климат
- реальные вузы, годы существования, специальности
- реальные методики: 12 шагов, Миннесотская модель, терапевтическое сообщество,
  КПТ, ДБТ, мотивационное интервьюирование
- вещества и типы зависимости, характерные траектории употребления
- типовые форматы программ и их сроки
- частотность имён и фамилий **по десятилетиям и регионам**

Последнее — пример того, зачем это нужно. Имена, популярные у рождённых в 1965
году, и у рождённых в 1995 отличаются. Модель этого не соблюдает никогда: она
выдаст один и тот же набор из десятка самых частотных имён на всю выборку.
Код — соблюдает, потому что берёт из таблицы.

## 1.2. Таксономии и шкалы

Как устроено пространство признаков предметной области.

| Шкала | Значения |
|---|---|
| Ценовой сегмент | эконом / средний / премиум, с диапазонами |
| Размер центра | малый 10–15 / средний 15–30 / большой 30–60 мест |
| Тип размещения | общая комната / 2–4 места / отдельная |
| Специализация | алкоголь / опиаты / стимуляторы / двойной диагноз / возрастные |
| Статус в каталоге | проверенный / непроверенный / чёрный список |

## 1.3. Архетипы — ядро фундаментального слоя

Архетип — **не конкретный человек, а порождающий шаблон**. Их немного: десятки,
а не тысячи. Именно поэтому их можно сделать качественно, вручную и с проверкой.

Пример архетипа консультанта:

```
АРХЕТИП: «Консультант из сообщества»
  происхождение     : бывший зависимый, выздоравливающий
  чистота           : 6–15 лет (обязательно > стажа работы)
  возраст           : 32–50
  образование       : чаще без профильного высшего; сертификаты сообщества
  путь              : употребление → программа → сообщество → работа консультантом
  компетенции       : группы, наставничество, работа с сопротивлением, кризис
  не может          : выступать в роли врача, назначать препараты
  лексикон          : «выздоровление», «программа», «спонсор», «срыв», «чистота»
  доля в популяции  : 40%

АРХЕТИП: «Клинический психолог, академический путь»
  происхождение     : без личного опыта зависимости
  возраст           : 28–45
  образование       : профильный вуз обязательно, часто аспирантура
  путь              : вуз → практика → специализация в аддикции
  компетенции       : КПТ, ДБТ, диагностика, работа с семьёй
  лексикон          : клинический, терминологический
  доля в популяции  : 25%
```

Архетип задаёт четыре вещи: **диапазоны** параметров, **обязательные связки**
(если бывший зависимый — обязаны быть история употребления и дата чистоты),
**запреты** (не может быть 25 лет и 20 лет стажа), и **характерный лексикон**,
которым потом будет писаться текст.

Так же устроены архетипы зданий («переоборудованная база отдыха советской
постройки», «частный коттедж в сосновом бору», «новый корпус»), архетипы
организаций, архетипы историй выздоровления.

## 1.4. Инварианты — правила, которые нельзя нарушить

Формальные, проверяются кодом, а не «просим модель не ошибаться».

```
возраст ≥ год_выпуска_вуза − год_рождения + 22
стаж ≤ возраст − 22
дата_чистоты ≤ дата_начала_работы_консультантом
специализация_центра ⊆ объединение специализаций персонала центра
вместимость_здания ≥ число_мест_программы
год_основания_центра ≥ год_постройки_здания
```

Нарушение инварианта — это не «плохой текст», это брак. Строка пересобирается.

## 1.5. Распределения

Как архетипы смешиваются в популяции: 40% одного, 25% другого и так далее.
Задаются один раз, применяются кодом ко всей выборке.

**Почему кодом, а не промптом.** Просьба «сделай 20% возрастных» на выборке в
300 штук не выполняется — модель не удерживает пропорции, она сваливается в
среднее. Код раскладывает 300 строк по долям детерминированно и точно.

# Часть 2. Карта пайплайнов

```
УРОВЕНЬ 0 — ФУНДАМЕНТ (разово, редко, качество критично)
  П0.1  Импорт справочников        ← реальные данные, не генерация
  П0.2  Создание архетипов         ← модель + обязательная ручная приёмка
  П0.3  Инварианты и распределения ← человек

УРОВЕНЬ 1 — БАЗОВЫЕ СУЩНОСТИ (массово, независимо, параллельно)
  П1  Персонал      ← архетипы личностей
  П2  Места         ← архетипы зданий и территорий
  П3  Методики      ← справочник методик + вариации
  П4  Организации   ← бренд, название, история

УРОВЕНЬ 2 — СОСТАВНЫЕ (ничего не сочиняют, только собирают)
  П5  Центр         ← отбирает из П1–П4
  П6  Отзывы        ← о конкретном центре и его конкретных людях

УРОВЕНЬ 3 — ПРОИЗВОДНОЕ
  П7  Изображения   ← сквозной, обслуживает П1, П2, П5
  П8  Тексты витрины ← описания, SEO, мета; зависят от П5
  П9  Связи         ← похожие центры, рейтинги, карта
```

**Порядок:** П0 → (П1…П4 параллельно) → П5 → (П6, П8, П9). П7 идёт сквозной
очередью и подхватывает задания от всех.

## Откуда берётся целостность

Правило одно: **каждый уровень не выдумывает, а конкретизирует предыдущий.**

- Уровень 1 не сочиняет людей с нуля — он создаёт **экземпляры архетипов**.
  Поэтому любые два консультанта одного архетипа согласованы между собой по
  логике, но различны по деталям.
- Уровень 2 не сочиняет вообще ничего — он **отбирает** из уровня 1. Центр для
  престарелых алкоголиков получает персонал, у которого в компетенциях
  действительно это, потому что отбор идёт запросом к базе, а не фантазией.
- Уровень 3 **пересказывает** уровень 2. Отзыв выпускника ссылается на реальных
  людей этого центра и реальную программу, потому что получает их на вход.

Целостность не проверяется в конце — она обеспечивается направлением потока.
Сущность физически не может сослаться на то, чего нет, потому что берёт ссылки
из базы, а не придумывает их.

# Часть 3. Пайплайн генерации персонала, по шагам

Живой пример. Постановка: **«300 консультантов РЦ, из них 20% с опытом работы
от 7 лет и сложной историей выздоровления»**.

### Шаг 1. Разбор постановки — модель, один вызов

Свободный текст → структурная спецификация. Модель получает список доступных
архетипов и раскладывает бриф.

```json
{
  "count": 300,
  "archetype_mix": {"консультант_из_сообщества": 0.75, "клинический_психолог": 0.25},
  "overrides": [
    {"share": 0.20, "constraints": {"стаж_мин": 7, "история": "сложная"}}
  ]
}
```

→ **Уходит человеку на утверждение.** Один дешёвый вызов, проверяется глазами
за минуту. Ошибку понимания ловим здесь, а не после 300 генераций за деньги.

### Шаг 2. План популяции — код, без модели

300 строк параметров. Для каждой:

1. выбрать архетип по распределению
2. взять из архетипа диапазоны → сэмплировать пол, возраст, регион, город
3. имя и фамилия из справочника **с учётом года рождения и региона**
4. вуз из реального списка, год выпуска согласован с возрастом
5. стаж, дата чистоты, вещество, траектория выздоровления
6. проверить инварианты; нарушение → пересобрать строку

Выход — таблица 300 × N, полностью детерминированная от сида. Одинаковый сид
даёт одинаковую популяцию.

**Это и есть фундаментальный слой в действии.** Здесь решено, каким будет
каждый из трёхсот человек. Модель к этому моменту ещё не вызывалась.

### Шаг 3. Уникальность плана — код + векторный индекс

Нет ли слишком похожих комбинаций внутри плана и относительно уже существующей
базы. Коллизия → пересэмплировать строку.

**Проверяем до обращения к модели.** Переставить параметры стоит ноль,
перегенерировать текст — деньги.

### Шаг 4. Постановка в очередь — код

300 заданий с естественными ключами. С этого момента прогон возобновляем:
падение сервера не теряет прогресс.

### Шаг 5. Генерация текста — модель, по одному заданию

На вход: строка параметров + лексикон архетипа + бриф.
На выход — структурированный JSON:

```
биография, профессиональный путь, подход к работе,
цитата, описание внешности для портрета
```

**Модель не выбирает факты — она их излагает.** Возраст, вуз, стаж, вещество
уже определены на шаге 2. Задача модели — написать живой текст по заданным
фактам, а не решить, каким будет сотый консультант.

### Шаг 6. Валидация — код

Факты в тексте совпадают с параметрами: возраст не «уплыл», вуз тот же, стаж не
переписан. Нет запрещённых формулировок. Длина в норме.
Провал → повтор с уточнением, что именно нарушено.

### Шаг 7. Уникальность текста — код + эмбеддинги

Текстовая близость (формулировки) и смысловая («тот же человек другими
словами») к уже существующим. Провал → перегенерация.

### Шаг 8–9. Портрет — код собирает промпт, модель рисует

Из параметров внешности и архетипа собирается промпт. Отдельная очередь,
отдельный воркер, другая стоимость и другой профиль отказов.

### Шаг 10. Сборка и отправка — код

Готовая запись + метка пачки → пачками по 250 в Nexorium.

### Шаг 11. Сверка — код

Если на отправке оборвался канал — исход неизвестен. Один запрос по метке пачки
разрешает: легла целиком / не легла / легла частично.

## Кто что делает — сводка

| Шаг | Исполнитель | Почему |
|---|---|---|
| 1. Разбор постановки | модель | понимание свободного текста |
| 2. План популяции | **код** | распределения и справочники модель не соблюдает |
| 3. Уникальность плана | **код** | это поиск, а не сочинение |
| 5. Текст | модель | это и есть её работа |
| 6. Валидация | **код** | модель не видит собственных расхождений |
| 7. Уникальность текста | **код** | модель не видит базу |
| 9. Портрет | модель | — |
| 10–11. Запись и сверка | **код** | — |

Модель вызывается дважды на сущность: текст и портрет. Всё остальное — код.
Это же и главный рычаг стоимости.

# Часть 4. Вопросы

1. **Архетипы — сколько и как заводим?** Предлагаю: 8–12 архетипов личности,
   5–7 зданий, 4–6 организаций. Создаются моделью, но принимаются вручную —
   их мало, а цена ошибки высокая: ошибка в архетипе размножится на тысячи
   экземпляров.

2. **Справочники — что импортируем, а что генерим?** Предлагаю импортировать
   реальные: регионы, города, вузы, методики, частотность имён. Иначе получим
   выпускников несуществующих вузов.

3. **Уникальность — на каком шаге по умолчанию?** Дешевле всего на шаге 3
   (параметры), дороже на шаге 7 (текст). Предлагаю оба, но шаг 3 обязателен.

4. **Отзывы — отдельный пайплайн или часть центра?** Предлагаю отдельный:
   у отзыва своя логика (от лица выпускника, ссылается на конкретных людей) и
   свой объём — их на порядок больше, чем центров.
